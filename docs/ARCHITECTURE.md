# Kiến trúc BrewLite

Frontend Next.js App Router, TypeScript, Tailwind CSS và CSS token của `stitch/**/DESIGN.md`. `app/` chỉ điều phối màn hình; `components/` chứa shell, auth provider, thành phần UI và tóm tắt; `stores/cart.ts` dùng Zustand persist; `types/domain.ts` giữ hợp đồng chung; `services/` chứa interface, mock và REST adapter. `NEXT_PUBLIC_DATA_MODE=mock|api` chọn adapter tĩnh; lỗi API không tự chuyển sang mock. Auth luôn gọi backend thật.

Backend NestJS modular monolith: `auth/` đăng ký, đăng nhập, cookie JWT, guard và role; `products/` đọc PostgreSQL; Prisma quản lý schema/migration/seed. Orders/Inventory đã có code TV4 (chờ DB verification); Payments, Promotions, Loyalty chưa có backend. PostgreSQL chạy qua Docker Compose hoặc cài riêng. Password băm bcrypt, role lấy từ DB khi xác thực, không tin role trong token hay body client. Cookie HttpOnly, SameSite=Lax, Secure khi NODE_ENV=production, path `/api`; middleware kiểm tra Origin cho các lệnh ghi bằng cookie. Logout xóa cookie ở browser; JWT stateless còn hợp lệ đến khi hết hạn nếu đã bị đánh cắp. Cần revocation/session table nếu yêu cầu hủy ngay trên mọi thiết bị.

Giỏ và đơn demo lưu localStorage theo browser; session người dùng khôi phục qua GET `/auth/me`. Backend không dùng dữ liệu demo. `POST /orders` phải tạo PENDING với giá được backend tính lại. `POST /payments` mới xác nhận PAID/PAYMENT_FAILED. UNKNOWN giữ nguyên trạng thái đến khi kiểm tra server. Mock ghi nhận idempotency key để tránh lặp và bảo toàn giỏ khi thất bại. Barista frontend chỉ hiển thị khi role BARISTA; backend staff API đã áp dụng `JwtAuthGuard` + `RolesGuard`.

Ảnh sản phẩm mock lấy URL gốc trong HTML Stitch; truy cập ảnh gốc cần mạng trên trình duyệt; SVG tĩnh dự phòng khi offline. Ảnh sản phẩm seed API lấy SVG tĩnh ở `frontend/public/images/products`.

OrdersModule dùng AuthModule + PrismaModule + InventoryModule. Tạo đơn tính giá từ catalog, chụp snapshot, giữ kho và lưu history trong một interactive transaction. Inventory dùng optimistic locking Product.version cùng điều kiện stock >= tổng qty theo product. Transition dùng Order.version và state machine, release/re-reserve trong cùng tx; OrdersService export hàm nhận transaction để TV5/TV6 ghi payment/loyalty nguyên tử. StaffOrdersController nằm trong OrdersModule và tái sử dụng đúng service này; không thay endpoint mẫu `/barista/dashboard` của TV1. Quy tắc cụ thể và giới hạn ở `API_CONTRACT.md`.
